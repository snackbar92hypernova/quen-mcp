# AGENTS: quen-mcp

quen is an MCP server and CLI that lets coding agents drive a game session for mod testing. It allows one driver at a time; it launches with settings overrides and mods parked, restores everything on every exit path, takes captures and A/B measurements, and keeps them in a SQLite ledger. **What quen is for, its principles and how it works: `docs/intent.md`; how an agent drives it, tool by tool: `docs/agents.md`** (served to agents as `quen_guide`). Platform-neutral logic lives in `crates/quen-core`, one module per piece (see its `lib.rs`); `crates/quen` is the binary: the stdio MCP front and the Windows layer, configured by the untracked local config (see its `config.rs`). `w3/` is quen's Witcher 3 game-side package (`W3Quen.asi` + the script mod `modQuen`, C++ and WitcherScript; see its README): its builds ship as GitHub Release assets of this repo. RE knowledge-base content and other Witcher 3 mods stay in the maintainer's `witcher3-mods` repo.

## Rules

- **No personal data, ever.**
  - Nothing that identifies the machine or its user: no user names, emails, machine names, home or install paths, save names, hardware details, Steam ids, or logs and screenshots from a real machine.
  - Use placeholders (`%USERPROFILE%`, `%GAME_DIR%`) and synthetic test data. Machine-specific values belong in the untracked local config.
  - The `pre-commit` and `commit-msg` hooks run two checks: `generic-scan`, patterns for user-folder paths, non-noreply emails and save-file names, and `deny-scan`, a deny-list kept outside the repo (`%USERPROFILE%\.quen\deny.txt`; before quen's move out of AppData, `%APPDATA%\quen\deny.txt`). Never bypass them (`--no-verify`), and never copy the list into the repo.
  - **Sessions without the deny-list** (cloud): don't set `core.hooksPath`. Run `sh .githooks/generic-scan "changes" $(git diff --name-only main)` yourself before each commit and push: CI runs the same scan only on pushes to `main` and on demand, not on a branch push. Work stops at "branch pushed": the maintainer runs the deny-list over the branch before anything is merged into `main`.
- **Source only.** This folder is for building the tool, never for what it produces when used. The ledger, captures, logs, journals and the local config live under the data root from the local config (default `%USERPROFILE%\.quen\`), outside this folder. Code must never default a data path inside the source tree, and must refuse one that points there.
- **Never in git:** build output (`target/`, `w3/out/`, release zips), the ledger database, captures, logs, files extracted or derived from a game, decompiled code, RE knowledge-base content.
  - One exception: `w3/asi/hooks.inc`, the package's hook table. Per hooked function it holds the RVA, the first 16 bytes of witcher3.exe 5.01 and the KB name, because the Tracy hooks need them at build time. Byte signatures and names only: no decompiled code, nothing else from the KB.
- **Core vs adapters:** game-agnostic code goes in the core, game-specific code in that game's adapter. Don't add an adapter for a game nobody is modding yet.
- **Refuse before acting:** every tool checks first and changes nothing when it refuses. After the first change, failures unwind through the session journal.
- **Shipped migrations are never edited, only added:** testers keep their ledger across quen updates, and theirs already ran the old text, so a fix is a new `schema/NNNN_*.sql`. quen-core's `tests/ledger_upgrade.rs` pins each file's sha256 (a new migration adds its pin) and upgrades a ledger from every older version. Every table, view and column is described in `schema/README.md`, which quen serves to agents; a test checks it names them all.
- Small, scoped changes; DRY; no single-use helpers or speculative abstractions.
- Every console program quen starts gets `CREATE_NO_WINDOW`. `quen serve` has no console, so Windows opens a terminal window for each one otherwise. Over a game, that steals focus, and focus loss pauses Witcher 3. Tests that take the foreground stay `#[ignore]`d.
- Rust: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` before reporting. CI runs the same, on Linux and Windows, on pushes to `main` that touch what the build reads, and on demand: `gh workflow run rust --ref <branch>`. Actions minutes are limited: dispatch only when a change needs it (never for docs the build doesn't read), one run at a time, since a newer run on the same ref cancels the one in progress.
- `w3/`: after a change, run `w3/asi/build.bat test` (MSVC, `WNB_SDK`) and the offline script compile (`w3/README.md`), and report the new sha256s. CI can't build it. Never launch the game or write into its folder: live tests are the maintainer's, through quen.
- Tests use synthetic fixtures only, written inline or generated by the test itself.
- Never delete user files permanently: Recycle Bin only.

## After a clone

1. `git config core.hooksPath .githooks`
2. Create the deny-list: one case-insensitive string per line, `#` for comments. Without it, the hooks refuse every commit.
